# Nemotron-H Lightning NVFP4 recipe: deviation table against verl#7688

Reference: `examples/grpo_trainer/run_deepseek_v4_true_on_policy_preview_megatron.sh` in [verl#7688](https://github.com/verl-project/verl/pull/7688) (DS4 exact 0-diff true-on-policy). Our recipe: `examples/grpo_trainer/run_nemotron_h_lightning_nvfp4_true_on_policy_megatron.sh` in an internal verl fork PR (head as of 2026-10-06). Both scripts were read from the file source, not the README; comparison date 2026-10-06. That PR's file list does not contain the Hydra config group `nemotron_h_true_on_policy/`, a sha256 manifest or a host memory check; those exist only on an old local branch (see open items at the end). Two-arm rules are in [bi-switch-recipe](../../skill/guides/recipe-evaluation/bi-switch-recipe.md), and the alignment method is in [recipe alignment](../../skill/guides/recipe-evaluation/01-recipe-alignment.md).

## Identical parts (not listed as deviations)

Algorithm and data: GRPO, `norm_adv_by_std_in_grpo=False`, KL fully off (`kl_coef=0`, `kl_loss_coef=0`), `clip_ratio_high/c = 0.28/10.0` (low uses the verl default 0.2), `loss_agg_mode` uses the verl default, `enable_thinking=True`, aligned mode train_batch 128 × n 8, mini batch 32, prompt 2048 / response 14000, DAPO reward (overlong buffer 4096, penalty 1.0, log False), seed 42 (same for data/rollout/actor), 100 steps, save 5 / test 10, `val_before_train=False`, `use_v1=False`, `max_actor_ckpt_to_keep=2`, critic off.

Optimizer (BI=1 arm identical to DS4 aligned): lr 1e-6, warmup 0, weight_decay 0.1, betas [0.9,0.95], `param_offload=False`, `optimizer_offload=True`, `offload_fraction=1.0`, `use_precision_aware_optimizer=True`, `decoupled_weight_decay=True`.

Training engine (BI=1 arm): `model_engine=mlite` (likewise injecting `model_engine/mlite.yaml` and `critic/mlite_critic.yaml` via a temporary Hydra searchpath), `engine.impl=vllm`, `engine.seed`, `engine.full_determinism=True`, `attention_backend_override=null`, `ppo_micro_batch_size_per_gpu=1`, `use_dynamic_bsz=True`, `log_prob_micro_batch_size_per_gpu=1`.

rollout: vLLM, TP1, `calculate_log_probs=True`, `update_weights_bucket_megabytes=1024`, `max_num_seqs=128`, `PYTHONHASHSEED=seed`, `PYTHONNOUSERSITE=1`, the W&B logger selection logic, the Ray runtime_env pass-through method, `DRY_RUN=1`/`COMPOSE_ONLY=1`; input validation only checks that `config.json` and data files exist.

## Deviation table

|---|---|---|---|---|

## Open items

- The checkpoint sha256 manifest, data sha256, host available memory ≥760 GiB check and the `ACCEPTANCE_STEPS=N` entry on the old local branch did not make it into the fork PR; the PR currently, like DS4, only checks file existence. Whether to add them back is undecided.
- Checkpoint rotation and "keep one fixed copy every 20 steps" ([checkpoint 05 §5](../../skill/guides/checkpoint-resume-memory/05-cluster-notes.md#5-rotation-retention-policy)) are done by the cluster-side `ckpt-rotate.sh` ([long-run-formal](reports/long-run-formal.md)); the recipe only has `max_actor_ckpt_to_keep=2`.
- The BI=1 arm's `gpu_memory_utilization` of 0.55 for dist_opt is a value measured to start successfully; the fsdp2 0.65 has not had the training process occupancy measured separately ([checkpoint 02 §5](../../skill/guides/checkpoint-resume-memory/02-host-memory.md#5-gpu-memory-trainingrollout-colocation-is-time-sharing-compute-per-phase)).
