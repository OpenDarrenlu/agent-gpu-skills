# 产出格式

仅在需要决定报告的交付格式，或需要产出 HTML 报告时读取本文件。用户明确指定格式时，按用户要求执行。

## 按场景选择

| 场景 | 默认格式 | 原因 |
| --- | --- | --- |
| 内部设计文档、PR 设计说明 | Markdown | 便于代码评审和版本比对 |
| 进 git 的分析报告，例如 `profile/<run_name>/REPORT.md` | Markdown | 与原始数据放在一起，便于复现 |
| 知乎、飞书、博客草稿 | Markdown | 平台可以导入；发布前把 Mermaid 导出为图片 |
| 篇幅短或以文字和表格为主的报告 | Markdown | 不需要额外排版 |
| 从截图、笔记或聊天记录整理的文章 | 单文件 HTML | 需要重绘原图并区分原文与补充 |
| 对外分享的长文 | 单文件 HTML | 版式稳定，离线可读 |
| 需要 3 幅以上精确示意图的报告（数据流、流水线时序、内存布局） | 单文件 HTML | 内联 SVG 可以精确表达位置和比例 |
| 需要交互的报告（切换 shape、过滤证据等级、折叠原始数据） | 单文件 HTML | 交互能回答评审问题 |
| 无法判断 | Markdown | 交付后说明可以转为 HTML |

不要为了装饰而选择 HTML。交互只在它能回答具体评审问题时使用。

## Markdown 约定

- 段落一段一行，标题、列表、表格和代码块结构保持原样。
- 补充内容：行内写「〔补充〕」；成段内容写成引用块，以「〔补充〕」开头。缺口写「〔待补充〕」「〔待确认〕」。
- 图的源文件（Mermaid、SVG、生成脚本和输入数据）放在报告旁边的 `figures/` 目录，使用描述性文件名，例如 `memory-flow.svg`、`pipeline-stages.mmd`。
- 链接使用相对路径或带 commit 的固定链接。
- 目标平台不渲染 Mermaid 或 LaTeX 时，导出图片或改用代码块中的纯文本，并在源文件中保留原始写法。

## 单文件 HTML 约定

从 [报告模板](../assets/report-template.html) 开始，替换占位内容：

- 自包含：CSS 和 JavaScript 内联，图使用内联 SVG，不加载外部字体、CDN 或远程图片，断网也能完整阅读。
- 结构顺序：元信息块 → 结论摘要 → 目录 → 正文 → 附录。主要结论写在普通文本中，JavaScript 不可用时仍然可见。
- 图：使用 `<figure>` 和 `<figcaption>`，图注包含编号、标题、证据等级标签和一句话结论；SVG 中的文字使用正文字体，保证可选中、可搜索。
- 证据等级标签：使用模板中的 `ev-*` 样式，例如「实测」「估算」「源码」「示意」。
- 「补充」标记：原材料之外新增的解释、背景和推导，行内使用 `<span class="badge-supplement">补充</span>`，成段内容使用 `<aside class="supplement">`。原文区块保持原样。
- 公式：离线环境无法加载 KaTeX 或 MathJax，使用 MathML、内联 SVG 或代码样式的纯文本公式。
- 版式：浅色主题，正文宽度适合阅读，表格可以横向滚动，提供打印样式。
- 交互控件可以用键盘操作，并保留标题、图注、替代文字和单位。

## 截图或资料整理成文

1. 逐张转写原文，保留原文用词、数字和结构；看不清的内容标「待确认」，不猜测。
2. 原图按原意重绘为内联 SVG，数据、标注和相对位置保持不变；无法确认的细节在图注中说明。
3. 新增的解释、背景和推导标注为补充（HTML 用补充徽标，Markdown 用「〔补充〕」），放在对应原文之后，不混入原文句子。
4. 术语和排版按本 Skill 统一，但不改变原文的事实、因果和确定程度。
5. 文末列出原始材料清单，例如截图编号、来源和日期。
