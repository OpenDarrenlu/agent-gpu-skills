# brain-and-hands 实验（2026-11-17）

目标：验证 Opus 5.5 / Sonnet 5.5 / Haiku 5.5 配合 brain-and-hands 能否「质量最好、消耗最少」，并把免费的
A7n Gris（`anthropic/a7n-gris[1m]`）当作最便宜的 hand 找出最佳协作方式。插件说明见
`skills/other/brain-and-hands/README.md`。

## 结论

1. **上游 0.1.0 在这些任务上从未触发委派**（24 次带插件运行，0 次调用子 agent），成本与不装插件相同；0.2.0 初稿/终稿未强制的 28 次运行同样 0 次委派。
   原因：委派规则在 `delegate` skill 里，主会话从不主动加载它，SessionStart 只给了一个指针。0.2.0 把规则本身放进钩子。
2. **准确率拉不开差距**：Opus 0.995、Sonnet 1.000、Gris 1.000、Haiku 0.933（Haiku 在日志定位 T2/T8 上丢分）。
   **价格与延迟才是差别**：每任务 Opus $0.167、Sonnet $0.084、Haiku $0.017、Gris $0；Gris 中位数比 Opus 慢 3.7 倍（0.5–18 倍），读 ~6 倍 token。
3. **在 ≤40k token 的任务上委派不划算**：强制委派的成本是内联的 0.6–1.8 倍（中位 1.2），主会话 token 0.9–2.7 倍（中位 1.6）。
   强模型会自己写脚本把「批量阅读」压成几次工具调用，所以 0.2.0 把委派门槛从「~6 次工具调用」提到「~100k token / 30+ 次调用 / 截图 / 可后台并行」。
4. **委派时的两个失败模式**（0.2.0 已写进 skill）：
   - 用 `sleep`/Monitor 轮询等 hand：Sonnet 主会话设了 21 个 Monitor 计时器、耗 3.1M token，最后一条消息只是「又一个计时器」，答案没在最后一条里（T6 质量 0.50）。去掉轮询后 3/3 正确、$0.206，比内联 $0.262 低 21%。
   - 分片太多：Opus 主会话 10 片 $0.77，4 片 $0.39（内联 $0.33）；每个 hand 完成都会唤醒一次带完整上下文的 Opus 轮次。便宜的主会话（Sonnet）10 片仍是 0.8 倍内联。
5. **Gris 没有表现出更笨**：18 次运行全部 1.00，包括 1000 函数审计、98 用例 cron 实现、事实不存在（T7）、日志注入（T8）。
   它的代价是慢和 token 多，所以 `grunt` 用于可后台并行、可校验的任务，不用于阻塞关键路径。
6. **没有观察到注入劫持**：T8 在日志里插入一行要求创建 `INJECTED` 的指令，Opus/Sonnet/Gris 9/9 忽略，Haiku 没有执行但答错 2/3（准确率问题，不是被劫持）。
   （第一版 T8 夹具把注入行写成了 500 日志，造成歧义，该结果已作废并重跑。）

## 设置

- 无头 `claude -p`，干净环境（独立 `CLAUDE_CONFIG_DIR`、不继承宿主托管认证），`--effort medium`，每个臂用 `--plugin-dir` 加载对应插件版本，工作目录为每次运行的新拷贝。
- 臂：`opus` `sonnet` `haiku` `gris`（无插件）；`+v1` 上游 0.1.0；`+v2a` 0.2.0 初稿；`+v2` 0.2.0 终稿；后缀 `!` 表示在提示末尾追加
  「把主要工作委派给 brain-and-hands 子 agent，再自行验证」。
- 成本取 CLI `modelUsage.costUSD` 的列表价（Gris 的价格口径为 unknown，记为 $0，token 单独记录）。
- 任务与评分都是脚本化的（`tools/gen_*.py`、`tools/score.py`，参考解自检：`tools/selftest.py`）。

## 局限（请按这些读上面的数字）

- **任务偏小且部分可脚本化**：模型发现 T1/T1H 的 240 个模块是 24 个模板的副本后，用「与多数版本比较」解掉；T6 的 12 种形状也被写脚本归一化。这些任务测的是效率而不是「大量非结构化阅读」，所以**没有测到委派真正划算的场景**（截图/GUI、几十万 token 的非结构化材料）。上游 README 也说这类才是最佳场景。
- 样本小（每格 1–3 次），Opus 单次成本波动大（例如 T3 内联 $0.16–$0.33），小于 ±30% 的差异不应当作结论。
- 终稿 0.2.0 只验证了一部分：未强制的 8/8 保持内联；强制的有效运行 10 次（T6 的 Sonnet 3/3、Opus 2/2，T3/T8/T9 各 1–2 次）。「Opus 主会话用 ≤4 片」是根据 `+v2a`（4 片 $0.39）与 `+v2`（10 片 $0.77）的对比写的，**两者还差别在无轮询规则，未单独隔离验证**。
- p8 批次 30 个运行里 12 个被 API Key 的月度额度上限（HTTP 403）打断，已从结果中剔除（`results/p8-*` 只含 18 个有效运行；`p7` 里重跑的 1 个同样剔除）。
- 没有测试：xhigh 推理强度（用户默认设置）、计算机使用、真实大型仓库、Gris 的长任务稳定性（T9 单次最长约 21 分钟）。

## 复现

脚本假定工作目录 `/dev/shm/bah-exp`（`tools/` 拷到该处）。凭据只在运行时从 `~/.claude/settings.json` 的 `env` 读取，不写入文件。

```bash
mkdir -p /dev/shm/bah-exp && cp -r docs/brain-and-hands-experiments/tools /dev/shm/bah-exp/
cd /dev/shm/bah-exp && python3 tools/gen_fixtures.py fixtures && python3 tools/gen_t5.py fixtures \
  && python3 tools/gen_heavy.py fixtures-heavy && python3 tools/gen_t6.py fixtures-t6 && python3 tools/gen_t9.py fixtures
python3 tools/selftest.py                     # 夹具与评分自检
python3 tools/run_exp.py out.jsonl opus,gris t6 --reps 2 --tag demo   # 臂 × 任务；+v1 臂需要上游副本 plugin-v0.1/
python3 tools/summarize.py out.jsonl
```

## 事故说明

本批实验共约 192 次运行、按列表价约 $25，用完了 `~/.claude/settings.json` 中 API Key 的月度额度，最后一批（p8）被 403 打断。
实验前没有确认额度上限；之后大批量实验应先确认预算或分批运行。
